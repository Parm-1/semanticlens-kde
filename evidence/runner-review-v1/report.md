## Findings requiring author repair

1. **Misreported transport failures and hidden service failures** — `src/runner/runner.cpp:35-65,96-108`. Every exchange failure becomes an actionable “KDE Index service is not running” match, including a connected server that times out and a connected server replying with an incompatible protocol or stale id. A well-formed `ok:false,error:...` reply disappears as an empty result list. In raw replay cases `connected-timeout`, `wrong-protocol` and `wrong-id`, the peer accepted the request, yet the native match says the service is not running. The timeout returned at 1113 ms with 111 main-thread timer ticks. The `server-error` case sent the permitted failure envelope `{protocol:1,id:<request>,ok:false,error:"wrong vector dimension"}` and produced zero matches. The current engine's `vectorBlob` throws that error for a malformed embedding vector; `handle` catches errors and the service wrapper adds protocol/id. This is a response-phase failure control, not a claim to have triggered that producer error in a real service. Distinguish cancellation, absence, timeout, invalid protocol and service failure in the exchange outcome, and present an honest bounded message for non-cancellation failures. Reserve “not running” for evidence of absence. Recheck the timeout/protocol/id/error controls and cancellation suppression after repair.

2. **Malformed rows become activatable file matches** — `src/runner/runner.cpp:109-137`. `score.toDouble(-1.0)` converts absent or string-valued scores to the valid lower endpoint. Both `missing-score` and `wrong-score-string` produce a file match with relevance 0 and path data rather than rejecting the row. `invalid-kind-page` supplies `kind:"executable",page:-3` and is also published as a file match. The documented producer contract supplies numeric score, `kind` in text/pdf/image, and positive 1-based pages for PDF or page 0 otherwise. Validate the required consumed field types and kind/page applicability before creating an action; a missing number must not impersonate a real -1 score. Recheck valid -1,0,1 endpoints, the exact-hit score 1 with semantic_score -0.5, text/image page 0, PDF page 3, and contradictory/missing raw fields. Do not add a semantic no-match threshold: the contract explicitly has none.

The author report additionally calls `score` a normalized dot score. Current engine search sets `score=1` for exact hits and otherwise clamps the dot, while `semantic_score` carries the dot. The adapter's mapping of `score` is useful and monotonic, but the description should identify the producer ranking score rather than claim that every mapped value is a raw dot.

## Source and native evidence

Exact matching-version primary source was fetched from KDE's v6.30.0 tag, stored and hashed under `local/runner-review-v1/upstream/`:

- [RunnerManager](https://invent.kde.org/frameworks/krunner/-/blob/v6.30.0/src/runnermanager.cpp): lines 206-210 move the C++ runner to a dedicated QThread; 290-292 queue `matchInternal` with a context copy; 472-481 invoke activation from the manager; 408-412 reset the context before runner teardown. The installed AbstractRunner header also explicitly places construction/run on the main thread and other runner methods off the UI thread.
- [RunnerContext](https://invent.kde.org/frameworks/krunner/-/blob/v6.30.0/src/runnercontext.cpp): lines 125-140 invalidate existing shared context copies under a write lock and detach a fresh valid context; 176-179 read validity under a read lock; 182-197 reject invalid contexts before publishing matches. Reset is the relevant lifecycle boundary, not an unrelated boolean flag.
- [AbstractRunner](https://invent.kde.org/frameworks/krunner/-/blob/v6.30.0/src/abstractrunner.cpp): lines 172-177 skip already-invalid jobs; match completion is reported after the synchronous method returns. This supports using a local blocking socket in the runner thread with bounded waits. The stack socket is created and destroyed inside match; run reads value data and does not share the socket. The serial is atomic.

Independent replay: `local/runner-review-v1/replay.cpp`, CMake source and `replay.jsonl`, loaded the unchanged module through real `RunnerManager::loadRunner/launchQuery`; the raw JSONL contains each request/reply, native matches, thread observation, timer count and peer-close observation. This is broader than the author's direct factory/match smoke, which never exercised RunnerManager threading or reset. The replay has 16 named cases, not 16 passing assertions. Thirteen accepted socket connections all observed peer closure; three cases never connected. `replay.stderr` is empty. Build/run exited 0.

Source-shaped positive result controls cover text, fragmented PDF JSONL with page 3, image with empty passage/page 0, and ranking score endpoints -1,0,1 mapping to relevance 0,0.5,1. The exact-hit control deliberately has score 1 and semantic_score -0.5, matching producer field semantics; it is not a probability claim. Numeric score 1.01 and relative paths were rejected. Wrong protocol/id were rejected as file results, with the misleading reporting described above. Fixture identity is a synthetic stub and does not establish model identity compatibility.

The reset control starts an actual native query, waits until its peer receives the request, calls `RunnerManager::reset`, then keeps that manager and its main event loop alive another 100 ms. It publishes no matches and its peer observes closure 25 ms after reset. All native runner objects were observed off the main thread. The connected timeout left the main event loop responsive. These are one bounded local replay each, not a live Plasma cancellation race or target latency distribution.

An additional observed behavior is that `Find storm shelter` never reaches the socket in default manager mode: `setTriggerWords` builds a case-sensitive regex, despite the candidate's case-insensitive check inside match. Lowercase `find ` works and unprefixed input is rejected. This does not block the stated lowercase-prefix contract; if uppercase support is intended, align the manager filter and repeat that native case.
