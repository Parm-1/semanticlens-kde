# KRunner adapter v2

This is the linked repair successor to frozen `evidence/runner-v1/`. It responds to the independent review in `evidence/runner-review-v1/report.md` (SHA256 `07d9e877e68a174bb75e78bb859e4fd36ba470b6857f8cab2fe2de0cd8ae919a`). Original v1 source, module, smoke, results, report and hash manifest remain unchanged; their manifest still verifies.

The adapter now distinguishes a missing local service from connection failure, connected timeout, invalid protocol/ID response and service `ok:false`. Cancellation caused by an invalid RunnerContext is suppressed; the runner aborts its per-request socket so the service observes disconnect. Connected timeouts no longer claim the service is absent. Only a socket absence offers the KDE Index setup launch result.

Result rows are admitted only when consumed fields have their required JSON types. `path`, `title`, `text`, and `kind` must be strings; `path` must be absolute and `title` nonempty. `kind` must be text, pdf or image. `page` must be an integral JSON number, positive for PDFs and zero for text and images. `score` must be a finite JSON number in [-1,1]. Text/PDF passages must be nonempty; empty image OCR text is allowed. Malformed rows are skipped without activating a file. The KRunner relevance mapping uses the producer ranking `score`, where exact hits are 1; `semantic_score` remains a separate dot field and is not used for ranking. The metadata license now matches the application's GPL-3.0-or-later license.

The real KF6 `RunnerManager` replay passed 26 asserted cases using an adapted successor copy of the original review harness. It loaded the native module, observed the runner on a worker thread, verified positive text/PDF/image results, fragmented JSONL, score endpoints, an exact score of 1 with semantic score -0.5, missing and contradictory row fields, invalid IDs/protocol, service errors, the connected timeout, service absence, and reset cancellation. The test kept the main event loop alive during reset and observed peer closure 25 ms later. The 1113 ms connected timeout allowed 111 main-loop timer ticks. Raw exchange evidence is `manager-replay.jsonl`; `tools/runner_v2_verify.py` contains the compact assertions.

An additional controlled integration used the actual CPU service and one synthetic text file under the explicitly selected test root. After indexing, the native RunnerManager queried the service through the adapter and returned the exact file with relevance 1. The service reported its model/producer identity; the receipt is `actual-service.json`. The service exited cleanly and its socket was removed. This validates one actual text path through service, protocol and KRunner mapping. It does not establish broad ranking, model, image/PDF, concurrency or target-desktop claims.

The standalone KF6 plugin build and native factory smoke passed.
