## Changed client contract and source boundary

Arbitrary source passage, title, path, warning, service/helper error and preview-message strings render as plain text, preserving markup characters and literal identifiers. All relevant Labels and editable/plain preview fields explicitly select plain text. The intentional fixed model-notice RichText/manual link activation remains. The generic dialog title is fixed `Preview`; the actual source title remains in an explicit plain-text header and the accessible name. The root path tooltip uses QtQuick.Templates ToolTip with only a plain-text content item. This matters on the actual KDE desktop style: overriding a styled tooltip's content item could still instantiate its discarded default AutoText label, and the default dialog header carries title text into an attached tooltip. These hidden surfaces must never receive arbitrary markup. Plain-text status uses an explicit Pane/Label instead of the styled rich-capable InlineMessage.

Linux process ownership is a detached launch PID plus `/proc/PID/stat` start ticks, with exited zombies excluded. The capture-owned shutdown hook additionally requires the connected Unix peer credentials (`SO_PEERCRED`) to match that live process and uid. Ordinary client destruction never kills or shuts down a common service. The client always tries the existing socket first; after a failed connection it may launch only when neither its owned identity nor a live process named by the data `service.lock` remains. An unreadable initial process identity with a possibly live PID blocks duplicate launches conservatively. Each recovery episode has at most 12 connection attempts and two launches; errors at the bound visibly request explicit Retry search. A successful connection starts a new episode. An owned shutdown hook suppresses relaunch; actual process loss does not.

This preserves the real engine's primary lifetime contract: data ownership is guarded by QLockFile; socket startup checks an existing live server before removing a stale endpoint; disconnect leaves the common service running. The GUI never kills a service. A replacement that wins before retry is reconnected and is not granted owned-shutdown authority. The exact intended Linux `/proc` and Unix-socket environment is the tested scope, not a portable process API or adversarial same-user sandbox. Simultaneous independent initial-client launch races beyond the real service's own lock/socket protection were not newly measured.

Usable inference now requires both service `ready` and `model_ready`; readiness loss invalidates cached results. Model file presence controls missing-model setup presentation only, and is not claimed to verify bytes. A connected unready service has a visible enabled Retry search action that sends deliberate `scan`; disconnected retry starts a fresh bounded connection episode. The source service error remains literal text; empty-error verifying snapshots say `Verifying search service…`, never `Ready`. Successful model-helper verification requests scan when connected, or attempts connection when disconnected. It no longer claims to start search without a service operation. Wipe retains its confirmation; no incompatible index is automatically removed.

The retained smoke runner observes the actual QML `closed` signal, invisibility and empty preview URL before independently asserting that the raster file is absent. Its 90-second total bound remains; the cleanup assertion is not weakened.
