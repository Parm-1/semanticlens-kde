## Batched actionable findings

### P1: Displaying a source excerpt fetches a URL without a user action

`../ui-v1/candidate/src/ui/Main.qml:166` binds arbitrary `modelData.text` to a Label using its default AutoText. Qt interprets a qualifying HTML excerpt, including image resources. The same issue should be checked for every data-derived Label/title/path/warning/message; the intentional fixed model-notice RichText at line 111 has a different source and purpose.

The source-shaped peer control returned `<b>source excerpt</b><img src='http://127.0.0.1:PORT/excerpt-canary.png'>`. The exact frozen QML rendered it and the independent loopback listener received a GET. The real-service control then indexed only the new synthetic `markup-corpus/markup.txt`, containing `<b>MARKUP-CANARY</b><img src='http://127.0.0.1:PORT/actual-service-canary.png'>`. There were zero HTTP fetches before the search. The actual staged service/producer returned this passage as an exact text result. Rendering caused one GET `/actual-service-canary.png`, with Host and Qt HTTP headers, without preview/open/reveal/link activation. `markup-final.json` contains the actual selected root, returned result fields and raw HTTP request; `peer-final.json` retains the controlled reply and raw HTTP request. `actual-markup.png` was independently inspected: the excerpt appears as bold MARKUP-CANARY, corroborating rich-text interpretation.

This contradicts the local-only/selected-root privacy contract. A remote URL in the same source position could receive a request; only loopback was contacted during review. Fix by rendering arbitrary content as plain text, including result/preview and status/error surfaces where applicable. Preserve literal identifiers and markup characters. Recheck with the actual indexed text input, source-shaped result/title/warning cases, a normal text/PDF positive, and a listener showing zero automatic requests.

### P2: A client that launched the service cannot recover after that service exits

`../ui-v1/candidate/src/ui/backend.cpp:92-104` launches only when attempts==1 and `!m_startedService`. A successful connection resets attempts, but the disconnected callback at lines 40-42 never clears or re-establishes ownership/liveness. Once startDetached succeeds, the flag remains true for the client's lifetime.

`real-final.json`: Backend launched the pinned real service with the existing readonly models, connected and became Ready. Its owned shutdown operation produced disconnection. After the bounded retry period it remained disconnected, its socket was absent, and the message was "Unable to connect to the search service. Restart the application to retry." A fresh Backend with the same paths immediately launched and connected successfully. In contrast, the independent peer control closes only the client connection while leaving a server available: reconnect succeeds and the current query is resubmitted. The defect is relaunch after process loss, not reconnect to an available socket.

Provide bounded recovery after the owned service has actually stopped, while preserving the common-service ownership semantics and avoiding duplicate launches against a live/replacement service. Track an appropriate process/liveness state rather than treating historical launch success as current liveness. Recheck an actual service exit or kill while the original Backend remains alive, successful current-query recovery after relaunch, and the existing-server reconnect control. Service engine-v2 integration requires a separate successor candidate and affected recheck.

### Validation defect: Preview cleanup is checked before the QML closed phase

Frozen `../ui-v1/candidate/tools/ui_smoke.cpp` invokes `preview.close()` and immediately asserts that the raster is absent. Frozen Main.qml cleans it at `onClosed` (line 75). Closing a Popup can animate; the close invocation is earlier than the closed event.

The independent exact staged ui-smoke exited 1 after 9889ms: six checks passed through real raster and page-window capture, then preview-temporary-file-removed was false (`smoke.json`). This does not demonstrate a permanent leak. `dialog-final.json` loads the exact QML and renders the real PDF page: immediately after close invocation the dialog remains visible and the raster/preview URL remain present; after the closed phase it is invisible, the URL is empty and the raster is absent. The cleanup control uses the actual UI phase and a bounded wait. Repair the retained harness's phase observation, then rerun the ten checks. Do not replace the cleanup assertion with an unconditional pass or infer immediate removal from parent green flags.
