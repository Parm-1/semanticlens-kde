# Local engine contract (candidate v1)

`kde-index-service --data-dir DIR --socket NAME --probe FILE --text-model FILE --image-model FILE [--threads 6] [--probe-sha256 SHA]` starts the service. All paths must be explicit. Data directory is private (0700). Default socket name is `kde-index-<uid>`; socket uses Qt user-only access. No default selected roots. `kde-index-cli --socket NAME '{"id":"cli-1","op":"status"}'` sends one request and waits for its matching response. The app can launch the service with these arguments, then connect via QLocalSocket. It must not open the database itself. Service remains running when clients disconnect; `shutdown` closes it explicitly.

One UTF-8 JSON object per newline, at most 64 KiB per request. String `id` is required and must be unique among a client's outstanding requests. Responses have `protocol:1,id,ok`; failures add `error`. Socket connection owns request identity. A disconnect cancels its pending requests. Service does not push unsolicited events. Cheap `status` is answered from a main-thread snapshot; poll every 500 ms while busy and less often idle.

Operations:

- `status`: response `status` object: `ready` (database/model identity verified), `model_ready`, `busy`, `paused`, `current` (path), `progress` (started file count, including `current`), `total`, `indexed` (files), `segments`, `errors` (files), `roots` (array of `{path,exclusions}`), `error` (startup/fatal error), `identity` (persisted model/pipeline identity), `index_revision` (persisted monotonic accepted-content revision), `failures` (up to20 `{path,error,warning}` records), `watch_error` (native watch coverage failure). Roots and counts are the canonical service snapshot.
- `add_root` / `remove_root`: `path` absolute selected directory. Selection resolves canonical path; nested/overlapping roots are rejected. Successful mutation returns `accepted:true` and schedules reconciliation.
- `set_exclusions`: `path` selected root, `exclusions` array of root-relative file/directory prefixes (no absolute paths, `..`, empty prefixes). Excluded active rows are removed before reconciliation; controls invalidate in-flight work.
- `scan`, `resume`: successful response `accepted:true`; scan is asynchronous. Inspect status until `busy:false`. Restart automatically reconciles configured roots.
- `pause`: invalidates unfinished work and stops scheduling new file work; accepted rows remain. `wipe`: removes all roots/files/segments and cancels unfinished work; model identity remains.
- `search`: `text` nonempty (<=2048 characters), optional `limit` 1..50 (default 20), `kind` empty/text/pdf/image. Response `results` array with `path,title,text,page,kind,score,semantic_score,exact,warning` for the best segment per file. `page` is 1-based for PDF and 0 otherwise; `kind` is text/pdf/image; `text` is source passage/OCR text (may be empty for images). Results also include `identity`, `generation` and `index_revision`. `score` stays in [-1,1]: exact/FTS hits receive1; other hits use clipped semantic dot. Exact hits sort before non-exact hits. `semantic_score` retains the actual normalized dot; these values are not probabilities; there is no validated no-match cutoff. Exact substring/FTS hits receive priority. File ranking is candidate behavior pending independent/release evaluation.
- `cancel`: `target` outstanding request id on the same socket. Returns `accepted:true` for a currently outstanding target (`false` for unknown targets); canceled search replies `ok:false,error:"canceled"`. New search does not automatically cancel old requests; clients should cancel and ignore stale ids.
- `shutdown`: response `accepted:true`, then service closes. Worker exits at idle (10 seconds), EOF then bounded terminate/kill fallback. Extraction/inference never runs in the socket or UI thread.

CPU weights are verified by pinned byte size and SHA256 before any vectors are accepted and before each worker reload. `--probe-sha256` supplies the expected executable digest from the accepted producer/build receipt; its default is the reviewed development binary f34469aa625f5000a7a3bb24a04b3c0cc91cf63ddb4e4a17fdbbf0fa1f49a9bf. A new build must supply its own checked digest. This argument pins executable bytes; it does not establish source/pipeline compatibility by itself. The executable SHA256 and full probe info are included in persisted identity; an identity mismatch refuses the database instead of mixing vectors. The binary's hardcoded info is not weight verification. A single worker thread owns SQLite and sequential producer/extractor processes; generations and source fingerprints guard accepted commits. Queries and controls run between indexing files. Cancellation can delay until the current bounded inference completes, but status/cancel ingress remains responsive. Local filesystem adversarial mutation races are not a security sandbox; roots should be directories owned by the user.

Supported indexing: txt/md, extractable-text PDF pages, JPEG/PNG visual embeddings and optional Tesseract OCR. Empty PDF pages up to page32 use Poppler rasterization (maximum1600 pixels on the longest edge) and Tesseract; later empty pages are skipped with an explicit warning. OCR failures are observable in status/result warnings, and a PDF with no readable pages is a file error. Image OCR passages also get document vectors; the visual segment keeps its independently produced image vector. File errors never receive fabricated vectors. Hidden files/directories, symlinks, credential/cache/build/generated directory names and credential filenames, engine-owned data, unsupported extensions, >32 MiB files and >256 segments are excluded or fail visibly. Each segment is at most 1800 characters; PDF extraction is capped at 2 MiB. Incremental reconciliation runs at restart, on explicit scan, and on native file/directory watcher events (350ms debounce). Watches cover only authorized nonexcluded paths, synchronize every500ms, and report installation failures; explicit scan remains available. Query and control work is scheduled between indexing files. Up to10000 eligible files per scan,256 outstanding worker tasks and64 outstanding requests per client are supported by this candidate. Removing or excluding content updates accepted rows before acknowledging the control. No personal directories are selected by tests.

`index_revision` is advanced by SQLite segment INSERT/DELETE triggers in the same transaction as accepted searchable content changes. Status publishes it after each file/control refresh; unchanged scans do not advance it. A query reports the revision of the database it read. Clients must observe status revisions, clear/cancel stale cached results and reissue a nonempty query when the revision changes; do not rely on seeing every busy transition. The revision persists across restarts. Indexing controls increment separate process-local generation to invalidate in-flight work. No filesystem race sandbox or corpus-wide semantic/no-match/latency acceptance is claimed by the small diagnostic integration controls. Character segmentation can still meet the producer token truncation boundary on token-dense text; multilingual coverage remains unbenchmarked. Vector storage records native float32 byte order and refuses incompatible persisted identity.
