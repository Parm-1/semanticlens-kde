## Primary contract and applicability

The local Linux statx ABI has no generic hydrated/resident/cloud-placeholder field. The primary man-pages `primary/statx.2` says unsupported stx_mask fields may contain dummy values, and attributes have usable meaning only where stx_attributes_mask supports the corresponding bit (lines304-318,434-440). AT_STATX_DONT_SYNC uses cached data if possible and can still involve remote work; AT_NO_AUTOMOUNT prevents automount only at the basename, not arbitrary ancestors (lines192-239). None is a no-network/content-read promise. STATX_ATTR_DAX is an access mode; it is not cloud residency.

Kernel6.18 `primary/fuse.rst` defines both metadata and data as userspace-provider supplied (lines9-18) and says the generic fuse source argument can be arbitrary (lines57-65). Therefore ordinary local path/regular-file/size/block/attribute responses, or a benign-looking subtype, cannot prove that a FUSE read or metadata request will avoid a fetch. Generic FUSE is a mechanism, not a local/remote classification. No provider fixture was mounted under this grant; no real cloud/FUSE/NFS folder was queried. Provider failure or ignored interrupt can also defeat a userspace wall-clock promise.

NTFS residency is specifically different: NTFS3 sets NI_FLAG_RESIDENT for MFT inline data, while larger normal files use runs (`primary/ntfs3-inode.c`). This is not hydration. Kernel6.18 NTFS3 exposes exact4-byte system.ntfs_attrib and system.ntfs_attrib_be (`primary/ntfs3-xattr.c`,789-805; official documentation https://docs.kernel.org/filesystems/ntfs3.html). OFFLINE is raw0x1000 (`primary/ntfs3-ntfs.h`,136). Missing/unsupported xattrs must not mean resident. The same version's ni_parse_reparse treats unknown NAME_SURROGATE tags as links, including the CLOUD0x9000001A family; readlink returns OneDrive for that family (`primary/ntfs3-frecord.c`,1751-1848; `primary/ntfs3-inode.c`,1987-2008). Existing symlink rejection supports this source representation. These are versioned primary Linux sources, not a live Windows placeholder/host NTFS3 fixture or a claim about every NTFS driver. Local NTFS3/exFAT compatibility should not be removed merely because generic FUSE semantics are unknown.

`primary/proc.rst`,1947-1957 documents mount ID, mountpoint and filesystem type; openat2's NO_XDEV includes bind mounts (`primary/openat2.2`,366-391). Mount information can classify the visible provider before selected-path stat/realpath. It does not certify the physical backing stack or provider honesty.

## Recommended bounded release contract, pending parent decision

Recommend a supported trusted-local-storage default, with an explicit future trusted-provider path rather than claiming universal hydration detection. A default storage-driver policy may permit established in-kernel local-storage types including ntfs3 and exfat, reject network/autofs/FUSE/overlay/unknown providers before selected-path metadata, and skip nested mount boundaries. An independently selected mount root may be admitted after its own policy checks. Exact allowlist and user-facing compatibility consequences require parent acceptance. Kernel storage can itself sit on remote block devices; the contract must state that the selected storage stack is trusted local storage. The app's process network restrictions cannot restrict another provider daemon.

Admission must precede QFileInfo canonicalization. Parse own mountinfo lexically with proper escapes and verify every ancestor provider; reject symlink components through kernel resolution, not a later final-component check. Hold a root fd and use fd-relative NO_XDEV/NO_SYMLINKS resolution for enumeration and content snapshot. Keep content hashing/extraction on the verified fd snapshot rather than re-opening the public path after a check. Ordinary read/hash/copy operations currently consume contents and can hydrate an arbitrary provider. Do not substitute xattr absence, mincore, FIEMAP, st_blocks, or a checker flag for provider proof. Treat mutable same-user provider/remount substitution and privileged backing-stack changes as outside this bounded trust contract; a cooperative no-hydration property is not an adversarial sandbox.

For local FUSE compatibility, branch B is explicit per-root/provider trust. Retain selected-provider support and explain that no generic residency guarantee is available; a later provider-specific interface can supply source-backed no-fetch semantics. This requires a persisted selection/API/UI contract beyond this package's write surface. Blanket generic FUSE admission silently as resident is unsupported. Branch A strict support would require clearly reported unsupported-provider rejection. Parent must select A/B or a narrower named provider contract before production policy code.

Enumeration repair is independently justified: stream directory entries without per-directory sorted lists; count every returned entry including ignored names, cap admitted directories, selected roots, queued paths/watches and accumulated path bytes, keep the existing10000 eligible-file cap, and inspect stop/cancellation between entries. Proposed finite first-release intervention:100000 total entries,10000 directories,64 selected roots,32MiB aggregate retained path storage; do not present these proposed values as accepted requirements or tested implementation. A wall-clock check between entries bounds cooperative work, not a blocked kernel call. Preserve sorting of the bounded final eligible-file list if deterministic file order matters.

On enumeration cancellation/error/limit, do not reconcile unseen rows as deletions: incomplete traversal is not absence evidence. Stop old scan/watch work observably, report the limit and recovery action, retain the last complete index only where its current admission policy still permits it. Root policy invalidation is different from incomplete enumeration: cached rows for inadmissible roots must be filtered before search and removed without opening source contents. On startup/restart/legacy databases revalidate root/mount admission before first crawl, watcher installation or cached-row search; retire old watches and stale content for rejected roots. Preserve accepted-control transaction/generation semantics, vector/extractor identities, literal/FTS/page association, failed extraction rows and explicit wipe. Policy changes do not authorize relabeling the old engine-v2 evidence.
