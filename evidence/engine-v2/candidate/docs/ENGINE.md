# Local engine contract (linked candidate v2)

`kde-index-service --data-dir DIR --socket NAME --probe FILE --text-model FILE --image-model FILE [--threads 6] [--probe-sha256 SHA]` starts the service. All paths must be explicit. Data directory is private (0700). Default socket name is `kde-index-<uid>`; socket uses Qt user-only access. No default selected roots. `kde-index-cli --socket NAME '{"id":"cli-1","op":"status"}'` sends one request and waits for its matching response. The app can launch the service with these arguments, then connect via QLocalSocket. It must not open the database itself. Service remains running when clients disconnect; `shutdown` closes it explicitly.

One UTF-8 JSON object per newline, at most 64 KiB per request. String `id` is required and must be unique among a client's outstanding requests. Responses have `protocol:1,id,ok`; failures add `error`. Socket connection owns request identity. A disconnect cancels its pending requests. Service does not push unsolicited events. Cheap `status` is answered from a snapshot with a separate short-lived lock, independent of SQLite commit serialization; poll every 500 ms while busy and less often idle.

Operations:

- `status`: response `status` object: `ready` (database/model identity verified), `model_ready`, `busy`, `paused`, `current` (path), `progress` (started file count, including `current`), `total`, `indexed` (files), `segments`, `errors` (files), `roots` (array of `{path,exclusions}`), `error` (startup/fatal error), `identity` (persisted model/pipeline identity), `index_revision` (persisted monotonic accepted-content revision), `failures` (up to20 `{path,error,warning}` records), `watch_error` (native watch coverage failure), `phase` (verifying/ready/failed/wiping), `recovery_attempt` (observable verification attempts). Roots and counts are the canonical service snapshot.
- `add_root` / `remove_root`: `path` absolute selected directory. Selection resolves canonical path; nested/overlapping roots are rejected. Successful mutation returns `accepted:true` and schedules reconciliation.
- `set_exclusions`: `path` selected root, `exclusions` array of root-relative file/directory prefixes (no absolute paths, `..`, empty prefixes). Excluded active rows are removed before reconciliation; controls invalidate in-flight work.
- `scan`, `resume`: successful response `accepted:true`; scan is asynchronous. Inspect status until `busy:false`. Restart automatically reconciles configured roots.
- `pause`: validates and commits persisted pause before invalidating unfinished file work; accepted rows remain. `wipe`: explicitly removes all owned roots/files/pages/segments even after incompatible stored identity. Its response separates `accepted` (removal operation committed), `removed` (owned database content removal completed), and `ready` (fresh current identity verified). Verification failure returns `ok:true,accepted:true,removed:true,ready:false,recovery_error`; status remains closed with an error. Partial filesystem removal failure returns `removed:false`, stays closed and requires deliberate retry. Wipe never auto-adopts old vectors. `scan` or `resume` explicitly retries current identity after a model failure; incompatible persisted identity still requires `wipe`.
- `search`: `text` nonempty (<=2048 characters), optional `limit` 1..50 (default 20), `kind` empty/text/pdf/image. Response `results` array with `path,title,text,page,kind,score,semantic_score,exact,term_match,match_type,match_scope,warning` for the best ranked passage per file. `page` is 1-based for PDF and 0 otherwise; `kind` is text/pdf/image; `text` is source passage/OCR text (may be empty for images). Results also include `identity`, `generation` and `index_revision`. `exact:true` means the complete trimmed query occurs literally, case-insensitively, with punctuation preserved in full source/page text or title. Literal hits precede token/FTS near-matches, which precede other semantic hits. `term_match` is a separate FTS5 token-match observation; `match_type` is literal/terms/semantic and `match_scope` is text/title/page/segment. `score` stays in [0,1]: literal=1, token tier=.90+.09*clipped((dot+1)/2), semantic tier=.89*clipped((dot+1)/2). Within each tier, actual semantic dot breaks ties, then path. The same comparator chooses the best passage per file. `semantic_score` retains the actual normalized dot; these values are not probabilities; there is no validated no-match cutoff. A full-source literal crossing a vector segment boundary is retained; its returned passage is a genuine source excerpt centered on the literal (at most query length+400 characters, hence <=2448). The associated semantic score comes from an actual vector on the same source page, without fabricating a vector for the excerpt. File ranking is candidate behavior pending independent/release evaluation.
- `cancel`: `target` outstanding request id on the same socket. Returns `accepted:true` for a queued or active target before its acceptance/commit point (`false` for unknown or already committed targets); canceled search replies `ok:false,error:"canceled"`. Control ingress is intent only. Rejected or canceled precommit controls do not persist pause/config changes or abandon an active scan. A mutex serializes cancellation against the sole SQLite writer's commit; after committed acceptance, cancellation returns false. `scan` stages enumeration before committing reconciliation. Accepted valid pause/root/exclusion/scan/wipe effects invalidate staged file work; checkpoints between embeddings prevent partial file vector commit. New search does not automatically cancel old requests; clients should cancel and ignore stale ids.
- `shutdown`: response `accepted:true`, then service closes. Worker exits at idle (10 seconds), EOF then bounded terminate/kill fallback. Extraction/inference never runs in the socket or UI thread.

CPU weights are verified by pinned byte size and SHA256 before any vectors are accepted and before each worker reload. `--probe-sha256` supplies the expected executable digest from the accepted producer/build receipt; its default is the reviewed development binary f34469aa625f5000a7a3bb24a04b3c0cc91cf63ddb4e4a17fdbbf0fa1f49a9bf. A new build must supply its own checked digest. This argument pins executable bytes; it does not establish source/pipeline compatibility by itself. The executable SHA256, full probe info, full-source representation3, pipeline `kde-index-full-pages-v3-segments1800-image140-ocr32`, native float ABI and actual pdftotext/pdfinfo/pdftoppm/Tesseract version strings are included in persisted identity; an identity mismatch refuses the database instead of mixing vectors. The binary's hardcoded info is not weight verification. A single worker thread owns SQLite and sequential producer/extractor processes; generations and source fingerprints guard accepted commits. Queries and controls run between file embeddings and between indexing files. Cancellation can delay until the current bounded inference completes, but status/cancel ingress remains responsive. Local filesystem adversarial mutation races are not a security sandbox; roots should be directories owned by the user.

Supported indexing: txt/md, extractable-text PDF pages, JPEG/PNG visual embeddings and optional Tesseract OCR. Empty PDF pages up to page32 use Poppler rasterization (maximum1600 pixels on the longest edge) and Tesseract; later empty pages are skipped with an explicit warning. OCR failures are observable in status/result warnings, and a PDF with no readable pages is a file error. Image OCR passages also get document vectors; the visual segment keeps its independently produced image vector. File errors never receive fabricated vectors. Hidden files/directories, symlinks, credential/cache/build/generated directory names and credential filenames, engine-owned data, unsupported extensions, >32 MiB files and >256 segments are excluded or fail visibly. Each segment is at most 1800 characters; PDF extraction is capped at 2 MiB. Incremental reconciliation runs at restart, on explicit scan, and on native file/directory watcher events (350ms debounce). Watches cover only authorized nonexcluded paths, synchronize every500ms, and report installation failures; explicit scan remains available. Query and control work is scheduled at file/embedding checkpoints. A single inference or extraction remains bounded work and may delay queued controls; cheap status/cancel ingress is independent. Up to10000 eligible files per scan,256 outstanding worker tasks and64 outstanding requests per client are supported by this candidate. Removing or excluding content updates accepted rows before acknowledging the control. No personal directories are selected by tests.

`index_revision` is advanced by SQLite full-source page INSERT/DELETE triggers in the same transaction as accepted searchable content changes. Status publishes it after each file/control refresh; unchanged scans do not advance it. A query reports the revision of the database it read. Clients must observe status revisions, clear/cancel stale cached results and reissue a nonempty query when the revision changes; do not rely on seeing every busy transition. The revision persists across restarts. Explicit wipe preserves and advances it through an owned `index-revision` checkpoint before deleting the database; a failed fresh verification does not reset the revision. Indexing controls increment separate process-local generation to invalidate in-flight work. No filesystem race sandbox or corpus-wide semantic/no-match/latency acceptance is claimed by the small diagnostic integration controls. Character segmentation can still meet the producer token truncation boundary on token-dense text; multilingual coverage remains unbenchmarked. Vector storage records native float32 byte order and refuses incompatible persisted identity.

This linked v2 changes persisted representation and intentionally rejects v1 databases; explicit wipe/rebuild is the supported recovery. The sealed v1 source/evidence remains recoverable under `evidence/engine-v1/candidate`. Fatal initialization and reload rejection close the heavy producer immediately, clear readiness and stop indexing while cheap status and explicit recovery controls remain available. Extractor versions are checked before reconciliation; unchanged data is never silently reused across extractor identity changes. No migration or automatic old/new vector mixing is permitted.
