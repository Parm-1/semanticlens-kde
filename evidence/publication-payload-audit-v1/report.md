## Findings

- **No concrete personal user configuration or credential file was identified in the bounded paths reviewed.** `evidence/embedding-v1/host.json` records CPU, kernel, architecture, Python/compiler versions and thread counts, not a username, home path, or secret. `evidence/desktop-boundary-v2/primary/installed-kde-portals.conf` (also copied to `evidence/desktop-open-v3/primary/installed-kde-portals.conf`) is retained in the export. The capture helper `evidence/desktop-boundary-v2/candidate/tools/desktop_layout_freeze.py` copies it from `/usr/share/xdg-desktop-portal/kde-portals.conf`; it contains only the package portal defaults (`default=kde`, Settings `kde;gtk`, Secret `kwallet`, Notification `plasmanotify`). This is a system package configuration snapshot, not the user's profile configuration, and contains no path/credential. The fresh profile's MIME association and test handler files are controlled evidence under `evidence/desktop-boundary-v2/raw/` and `evidence/desktop-open-v3/raw/`, not user-home config. Absence in this bounded read is not proof that every private datum is absent.

- **Benchmark demo data has explicit provenance and license.** `benchmark/README.md` states all 28 corpus files, vector artwork, rendered images and labels are original synthetic project material, with no personal data or borrowed photos, dedicated under CC0-1.0; `benchmark/LICENSE` supplies the CC0 text and `benchmark/SHA256SUMS` pins the frozen corpus/labels/contract. The existing 28-file/37-query benchmark inventory is the relevant check category.

- **Embedding photo/screenshot fixtures have synthetic provenance but no explicit output-asset dedication.** `evidence/embedding-v1/report.md` identifies the exact upstream DigUp commit `6faa29e4c315a3a591de1b41bd78751bdf39588d` and says the copied source, prompts, model pins, tests, patch and synthetic-generation source are under MIT notice. `evidence/embedding-v1/source/make_reference_inputs.py` deterministically generates `inputs/screen.png` and `inputs/photo.jpg` from arrays/shapes/noise and explicitly describes them as synthetic, with no personal or third-party media. `ReferenceVectorTests.swift` confirms these are the fixed screenshot/photo fixture inputs. The repo retains `source/DigUp-LICENSE`, `source/llama.cpp-LICENSE`, candidate probe notices and 52-line `SHA256SUMS`. The evidence does not separately state a license/dedication for the generated image bytes; settle that asset notice/provenance before treating these fixtures as independently cleared public demo assets. No evidence indicates they are real user photographs.

- **Upstream reference snapshots retain original license headers; the inventory exposes custom alternatives.** `evidence-source-licenses/README.md` says snapshots are reference evidence, not linked application code; `source-identifiers.json` inventories 68 header-bearing paths and preserves original expressions. GNU GPL/LGPL texts are pinned in `sources.json`; root `LICENSE` is GPL-3.0. Twenty inventory paths contain a `LicenseRef-*` option: notably `LicenseRef-KDE-Accepted-LGPL` and `LicenseRef-Qt-Commercial` in KDE/Qt source headers (examples: `evidence/desktop-boundary-v2/primary/installed-ResultsView.qml`, `kf-resultsmodel-v6.30.0.cpp`, `qquickwindow-v6.12.0.cpp`). The local evidence-license notes do not define these LicenseRef terms, though the same expressions also offer standard LGPL/GPL alternatives whose texts are present. The source supports preserving those headers and standard alternatives; it does not establish a project-wide selection or resolve the custom alternatives. If the public source package relies on a `LicenseRef` option, add its authoritative license reference/notice; otherwise retain the original headers and standard license texts and avoid claiming that this bounded 68-header inventory is a complete clearance.
